# 摩斯外賣銷售記錄 App - 實作規格 (spec.md)

## 專案背景
個人側專案,用於記錄早班外賣工作的每日銷售狀況(捷運站小推車販售,
品項為預先做好的三明治、漢堡、飲料)。單人使用,無需登入、無需雲端同步。

## 技術棧
- 前端:React(建議用 Vite 建置)
- 打包:Capacitor,產出可安裝的 Android APK
- 儲存:裝置本機儲存(localStorage 或 Capacitor Preferences,擇一即可,
  不需要雲端同步)
- UI 語言:繁體中文
- 程式碼與註解:英文

## 架構說明(建議,非強制)
這是單人、單裝置、純本機儲存的 App,不需要 3-tier 架構或多個獨立
service/後端——沒有網路呼叫、沒有需要多方存取同一份資料的情境。

建議依關注點分離,結構清楚、好維護(細節見 `CLAUDE.md`):
- `components/`   — 畫面元件、事件綁定
- 業務邏輯          — 新增/編輯/刪除品項、+1/-1 計算、換日判斷、套用
                     常用品項範本,建議抽成純函式或 custom hook
- `services/storage.js` — 讀寫本機儲存的建議統一入口

這是建議的組織方式,不是必須遵守的限制,依實際開發彈性調整即可。

## 資料模型

### 一般品項(三明治、漢堡類)— 每日資料
```json
{
  "id": "唯一識別碼",
  "type": "regular",
  "name": "品項名稱,例如:培根蛋三明治",
  "stock": 20,        // 今日備貨數量,每日可編輯
  "price": 35,         // 單價,每日可編輯
  "sold": 0            // 已售數量,+1/-1 按鈕操作
  // 剩餘數量 = stock - sold
}
```

### 飲料品項 — 每日資料
```json
{
  "id": "唯一識別碼",
  "type": "drink",
  "name": "品項名稱,例如:紅茶",
  "stock": 20,          // 共用備貨數量(套餐+單點共用同一批庫存)
  "comboPrice": 25,     // 套餐價
  "aLaCartePrice": 35,  // 單點價
  "comboSold": 0,       // 套餐已售,+1/-1 按鈕
  "aLaCarteSold": 0     // 單點已售,+1/-1 按鈕
  // 剩餘數量 = stock - (comboSold + aLaCarteSold)
}
```

### 常用品項範本(獨立於每日資料)
```json
{
  "id": "唯一識別碼",
  "type": "regular" 或 "drink",
  "name": "品項名稱",
  "defaultStock": 20,          // 預設備貨量
  "defaultPrice": 35,          // 一般品項預設單價
  "defaultComboPrice": 25,     // 飲料預設套餐價
  "defaultALaCartePrice": 35   // 飲料預設單點價
}
```
- 獨立儲存,不隨「今天/昨天」資料的換日輪替而清空
- 需支援新增/編輯/刪除範本品項

## 資料保留邏輯
- App 記錄「今天」與「昨天」兩份資料(背景可多留一天前天作保險,共 3 天輪替)
- 每次開啟 App 時,檢查裝置日期是否已換日:
  - 若已換日:將目前「今天」的資料存為「昨天」,原本的「昨天」變成「前天」
    (前天資料超過範圍後直接捨棄,不需額外畫面查看)
  - 「今天」資料重置為空白,等待使用者重新設定當日品項
  - 若未換日:維持現有資料,不做任何搬移
- 常用品項範本不受此換日邏輯影響,永久保留直到使用者手動修改

## 畫面需求

### 單一主頁面,含兩個頁籤切換:「今天」/「昨天」

**「今天」頁籤(可編輯)**
- 頁面最上方兩個按鈕:
  - 「+ 新增品項」:彈出表單,選擇品項類型(一般/飲料),填寫名稱、
    備貨數量、價格(飲料需填套餐價與單點價),新增到今天清單
  - 「套用常用品項」:將常用品項範本整批複製到今天的品項清單,已售數量
    (sold / comboSold / aLaCarteSold)一律歸零,備貨量與價格帶入範本的
    預設值;使用者可自行刪除今天沒有要賣的品項、或編輯數量與價格,
    這些變動只影響今天資料,不會回寫範本(採方式 A:整批套用後手動刪除,
    不做套用前勾選介面)
- 品項列表,每個品項顯示:
  - 品項名稱
  - 備貨數量、單價(一般品項)或套餐價/單點價(飲料),旁邊有「編輯」按鈕
    可修改這些數值
  - 已售數量與 [−1] [+1] 按鈕(飲料則是套餐已售/單點已售各自一組
    [−1] [+1] 按鈕)
  - 剩餘數量(即時計算顯示)
  - 「刪除」按鈕移除該品項
- 操作需即時反應(按下 +1/−1 立即更新畫面與存檔),不需要額外的
  「儲存」按鈕

**「昨天」頁籤**
- 顯示昨天最終的品項清單與各項最終銷售數字(備貨、已售、剩餘)
- 規劃上為查看歷史紀錄用,預設不提供編輯/新增/刪除功能

**「管理常用品項」(獨立入口,可為另一頁面或彈出視窗)**
- 顯示常用品項範本清單
- 支援新增/編輯/刪除範本品項(名稱、預設備貨量、預設價格)

## 非功能需求
- 優先簡單可靠,避免過度工程化,不需要複雜的狀態管理框架
- 動畫效果非必要,但允許加入(例如按鈕回饋、頁籤切換過場)
- 不需要多使用者支援、不需要資料匯出/報表功能(除非之後明確要求)
- 不需要網路連線即可完整運作
- 目標是明天就能實際上工使用,若時間不足,可先求「今天」頁籤功能完整、
  「昨天」頁籤與「常用品項範本」可以晚一點再補

## 交付項目
1. 可運作的網頁版本(先用瀏覽器測試功能正確)
2. 使用 Capacitor 打包後,可安裝到 Samsung Android 手機的 .apk 檔案
3. 簡單的建置/安裝步驟說明(給非 Android 開發背景的使用者看)
